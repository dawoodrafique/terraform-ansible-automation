## 🔭 What This Layer Does

Running `ansible-playbook -i inventory.ini playbook.yml` will, on every host in the inventory:

1. **Detect the OS family** using Ansible facts (`ansible_os_family`, `ansible_distribution`)
2. **Install Nginx** using the correct package manager for that OS
3. **Copy `index.html`** to the OS-appropriate web root directory
4. **Enable and start** the Nginx service so it survives reboots
5. **Notify handlers** to restart Nginx if any configuration changed

The role is fully **idempotent** — running the playbook multiple times leaves the system in exactly the same state.

## ✅ Prerequisites

- [Ansible](https://docs.ansible.com/ansible/latest/installation_guide/) ≥ 2.14
  ```bash
  # Install pipx for ubuntu
  sudo apt update
  sudo apt install pipx

  # Install ansible for ubuntu
  pipx install --include-deps ansible
  ```

- `ansible/inventory.ini` already generated by Terraform (see [`terraform/README.md`](../terraform/README.md))
- Port 80 open inbound on the host security group

## 📋 Inventory

`inventory.ini` is written automatically by Terraform and should **never be edited by hand**. Re-run `terraform apply` to regenerate it whenever infrastructure changes.

Typical structure:

```ini
[all:vars]
ansible_ssh_private_key_file=~/.ssh/tf-ansible-key
ansible_python_interpreter=/usr/bin/python3
ansible_host_key_checking=false


[servers]
# It has both control-ubuntu and the 
control-ubuntu ansible_host=<control-ubuntu-public-ip> ansible_user=ubuntu
worker-ubuntu ansible_host=<worker-ubuntu-ip> ansible_user=ubuntu


worker-amazon ansible_host=<worker-amazon-ip> ansible_user=ec2-user


worker-redhat ansible_host=<worker-redhat-ip> ansible_user=ec2-user


```
- `servers` — all hosts that should receive Nginx (can be mixed OS)

## 📄 Playbook

`playbook.yml` is the single entry point. It applies the `nginx` role to every host in the inventory:

```yaml
---
- name: Install and configure Nginx on all hosts
  hosts: all
  become: true
  roles:
    - nginx
```

`become: true` is required because installing packages and writing to `/var/www/html` need root privileges.

## 🎭 Role: nginx

The role was initialised with `ansible-galaxy role init nginx` and follows Galaxy's standard directory layout. All OS-specific logic is fully isolated in separate task files — the role entry point and the playbook remain OS-agnostic.

---

### Defaults — `defaults/main.yml`

Conservative, safe defaults. Override them in your playbook's `vars`, in `group_vars`, or on the CLI with `-e`.

---

### OS Dispatcher — `tasks/main.yml`

Ansible's gathered facts expose `ansible_os_family` and `ansible_distribution` at runtime. The dispatcher uses `include_tasks` with a `when` condition to route execution to exactly one OS-specific file — no duplication, no scattered conditionals:


---

### OS-Specific Task Files

Each file is responsible for three things on its target OS: installing Nginx, copying `index.html` to the correct web root, and notifying the appropriate handler.

| File | Target OS | Package Manager | Web Root |
|---|---|---|---|
| `amazon_spec_tasks.yml` | Amazon Linux 2 / 2023 | `amazon-linux-extras` / `dnf` | `/usr/share/nginx/html/` |
| `redhat_spec_tasks.yml` | RHEL 8/9, CentOS Stream | `dnf` | `/usr/share/nginx/html/` |
| `ubuntu_spec_tasks.yml` | Ubuntu 20.04 / 22.04 / 24.04 | `apt` | `/var/www/html/` |

**Amazon Linux (`amazon_spec_tasks.yml`) — key steps:**
- On Amazon Linux 2: enable the `nginx1` extra via `amazon-linux-extras`, then install
- On Amazon Linux 2023: install directly via `dnf` (extras not available)
- Copy `../../index.html` to `/usr/share/nginx/html/index.html`
- Notify `Restart Nginx`

**RHEL / CentOS (`redhat_spec_tasks.yml`) — key steps:**
- Install `nginx` via `dnf`
- Copy `../../index.html` to `/usr/share/nginx/html/index.html`
- Notify `Restart Nginx`

**Ubuntu / Debian (`ubuntu_spec_tasks.yml`) — key steps:**
- Run `apt update`
- Install `nginx` via `apt`
- Copy `../../index.html` to `/var/www/html/index.html`
- Notify `Restart Nginx`

---

### Handlers — `handlers/main.yml`

Two handlers are declared and triggered via `notify` inside the task files. They execute **only when a preceding task reports a change** — not on every run.


This makes the role efficient and truly idempotent — a second run with no changes produces no service restarts.

---

### Vars — `vars/main.yml`

Role-scoped overrides that take precedence over `defaults/main.yml`. Use this file for values that should always apply to this role, regardless of how it is invoked:

```yaml
---
# Override here to change values for all consumers of this role
# nginx_port: 8080
```

Leave this file empty (or minimal) if `defaults/main.yml` values are sufficient. Prefer `group_vars` or playbook-level `vars` for environment-specific overrides.

## 🌐 index.html

`ansible/index.html` is the custom landing page deployed to every host. It is copied verbatim to the OS-appropriate Nginx web root during the playbook run. Edit this file before running the playbook to customise what visitors see.

Default web root locations by OS:

| OS Family | Web Root |
|---|---|
| Ubuntu / Debian | `/var/www/html/index.html` |
| Amazon Linux / RHEL | `/usr/share/nginx/html/index.html` |

## 📋 Variables Reference

| Variable | Scope | Type | Default | Description |
|---|---|---|---|---|
| `nginx_port` | `defaults` | `int` | `80` | Port Nginx listens on |
| `nginx_enabled` | `defaults` | `bool` | `true` | Enable and start Nginx at boot |

To override at the playbook level:

```yaml
- hosts: all
  become: true
  roles:
    - role: nginx
      vars:
        nginx_port: 8080
        nginx_enabled: true
```

## 🚀 Usage

```bash
# From the ansible/ directory

# Run the full playbook against all hosts
ansible-playbook -i inventory.ini playbook.yml

# Dry run — show what would change without making changes
ansible-playbook -i inventory.ini playbook.yml --check

# Run only against the webservers group
ansible-playbook -i inventory.ini playbook.yml --limit webservers

# Override a variable at the CLI
ansible-playbook -i inventory.ini playbook.yml -e "nginx_port=8080"

# Verify Nginx version on every host after the run
ansible all -i inventory.ini -m command -a "nginx -v"

# Verify the index page is being served
ansible all -i inventory.ini -m uri -a "url=http://localhost return_content=yes"
```
