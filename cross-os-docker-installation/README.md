> **Automated Docker deployment across Amazon Linux, RHEL, and Ubuntu — powered by Terraform and Ansible.**

Provision a full AWS VPC stack with Terraform, auto-generate your Ansible inventory, and install Docker across multiple Linux distributions using a single, OS-aware Ansible role.

## 🔭 Overview

This project automates the entire lifecycle — from cloud infrastructure to software configuration — in two clean phases:

| Phase | Tool | What It Does |
|---|---|---|
| **Provisioning** | Terraform | Creates VPC, subnets, gateways, security groups, and EC2 instances |
| **Configuration** | Ansible | Detects OS family, installs Docker, adds users, enables the service |

The two phases are connected by a **dynamically generated `inventory.ini`** — Terraform writes it automatically after provisioning, so Ansible always has the correct host IPs without any manual intervention.

## 🏛️ Terraform Layer

### Module Breakdown

Every AWS resource is encapsulated in a dedicated module. The root `main.tf` wires them together — outputs from one module feed as inputs to the next, forming a clean dependency chain with no hardcoded values.

| Module | Key Resources | Key Outputs |
|---|---|---|
| `vpc` | `aws_vpc` | `vpc_id` |
| `subnets` | `aws_subnet` (×2) | `public_subnet_id`, `private_subnet_id` |
| `internet-gtw` | `aws_internet_gateway` | `igw_id` |
| `nat-gtw` | `aws_nat_gateway`, `aws_eip` | `nat_gateway_id` |
| `route-tables` | `aws_route_table`, `aws_route_table_association` | `public_rt_id`, `private_rt_id` |
| `sg` | `aws_security_group` | `sg_id` |
| `ec2` | `aws_instance` | `public_ip`, `private_ip` |

### Creating Public vs Private EC2 Instances

The same `ec2` module is called twice — once with the public subnet, once with the private(If you want a private ec2 instance). This is the key reusability pattern of this project.


### Dynamic Inventory Generation

After `terraform apply`, the `inventory-generator.tf` uses Terraform's `templatefile()` function to render `inventory.tpl` with real EC2 IPs, writing the result directly to `ansible/inventory.ini`. No manual steps required.


### Take A Look At Inventory Template
[Inventory Template](./terraform/templates/inventory.tpl)

> ⚠️ **Cost Warning:** The NAT Gateway incurs AWS charges even when idle. Always run `terraform destroy` when the environment is no longer needed.

## ⚙️ Ansible Role

The role was bootstrapped with `ansible-galaxy role init docker` and follows Galaxy's standard directory layout. OS-specific logic is fully isolated in task files — the playbook and role entry point remain entirely OS-agnostic.

### Defaults — `defaults/main.yml`

Conservative, safe defaults. Docker is installed but neither enabled nor assigned users unless you explicitly override these.

```yaml
---
# Users to add to the docker group (allows running docker without sudo)
docker_users: []

# Set to true to enable and start Docker at boot
enabled_docker: false
```

### OS Dispatcher — `tasks/main.yml`

Ansible facts detect the OS family at runtime and delegate to the appropriate task file. No duplication, no conditionals scattered across tasks.

### OS-Specific Task Files

| File | Target OS | Package Manager | Repo Method |
|---|---|---|---|
| `amazon_spec_tasks.yml` | Amazon Linux 2 / 2023 | `amazon-linux-extras` / `dnf` | Built-in extras or official Docker repo |
| `redhat_spec_tasks.yml` | RHEL 8/9, CentOS Stream | `dnf` | `download.docker.com/linux/centos` |
| `ubuntu_spec_tasks.yml` | Ubuntu 20.04 / 22.04 / 24.04 | `apt` | Docker GPG key + APT repository |

### Handlers — `handlers/main.yml`

Two handlers are registered and triggered via `notify` inside task files. They execute only when a change actually occurs — idempotent by design.

## 🔄 End-to-End Workflow

```
Step 1 — Configure Variables
   └─ Edit terraform/variables.tf or create terraform.tfvars
      Set: region, AMI IDs, instance type, CIDR blocks, key pair name

Step 2 — Initialize & Apply Terraform
   └─ terraform init
      terraform plan
      terraform apply
      → VPC, subnets, gateways, security groups, EC2s are created

Step 3 — Inventory Auto-Generated
   └─ local_file resource renders inventory.tpl → ansible/inventory.ini
      → No manual IP copy-paste needed

Step 4 — Run the Ansible Playbook
   └─ cd ansible/
      ansible-playbook -i inventory.ini playbook.yml
      → Role detects OS per host, runs the correct task file

Step 5 — Verify
   └─ ansible all -i inventory.ini -m command -a "docker --version"
      → Confirms Docker is installed on every host

Step 6 — Teardown (when done)
   └─ cd terraform/
      terraform destroy
```
> 💡 **SSH to public control-ubuntu**:
> ```bash
> ssh -i ~/.ssh/your-key.pem ubuntu@<public_ip>
> ```


> 💡 **SSH to private instances** through the public bastion host(When you need private control-ubuntu):
> ```bash
> ssh -J ubuntu@<public_ip> ubuntu@<private_ip>
> ```
> Make sure your SSH agent is forwarding: run `ssh-add ~/.ssh/your-key.pem` first.

## 📋 Variables Reference

### Terraform — `terraform/variables.tf`

| Variable | Type | Default | Description |
|---|---|---|---|
| `aws_region` | `string` | `"us-east-1"` | AWS region to deploy into |
| `vpc_cidr` | `string` | `"10.0.0.0/16"` | CIDR block for the VPC |
| `public_subnet_cidr` | `string` | `"10.0.1.0/24"` | CIDR for the public subnet |
| `private_subnet_cidr` | `string` | `"10.0.2.0/24"` | CIDR for the private subnet |
| `instance_type` | `string` | `"t3.micro"` | EC2 instance type |
| `key_name` | `string` | — | AWS key pair name for SSH access |
| `ami_id` | `string` | — | AMI ID for EC2 instances |

### Ansible Role Defaults — `defaults/main.yml`

| Variable | Type | Default | Description |
|---|---|---|---|
| `docker_users` | `list(string)` | `[]` | OS users to add to the `docker` group |
| `enabled_docker` | `bool` | `false` | Enable and start Docker on boot |

## 🚀 Quick Start

### Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/install) ≥ 1.5
- [Ansible](https://docs.ansible.com/ansible/latest/installation_guide/) ≥ 2.14 (`pip install ansible`)
- [AWS CLI](https://aws.amazon.com/cli/) configured with appropriate IAM permissions
- An existing AWS EC2 key pair

### Full Deployment

```bash
# 1. Clone the repository
git clone git@github.com:<your-username>/<your-repo>.git
cd cross-os-docker-install

# 2. Provision infrastructure
cd terraform
terraform init
terraform plan -var "key_name=my-keypair"
terraform apply -var "key_name=my-keypair" -auto-approve

# We will use Remote ec2(control-ubuntu) as our ansible master
# Upload the key to the remote instance
scp -i ~/.ssh/tf-ansible-key  ~/.ssh/tf-ansible-key ubuntu@<control-ubuntu-public-ip>:/home/ubuntu/.ssh/


# When you create(First Time) and update your ansible code in the local system just upload the updated file to the remote instance
rsync -avz -e "ssh -i ~/.ssh/tf-ansible-key" \                                                               
  --rsync-path="mkdir -p /home/ubuntu/ansible && rsync" \
  ./ansible/ ubuntu@<control-ubuntu-public-ip>:/home/ubuntu/ansible/

# 3. Run Ansible — inventory.ini is already written by Terraform
cd ../ansible
ansible-playbook -i inventory.ini playbook.yml

# 4. Verify Docker on all hosts
ansible all -i inventory.ini -m command -a "docker --version"

# 5. Teardown when done
cd ../terraform
terraform destroy -auto-approve
```



## 📌 Notes & Best Practices

- **Remote State:** Configure `backend.tf` with an S3 bucket and DynamoDB table for state locking before working in a team.
- **AMI Selection:** Use separate AMI IDs per OS if you want to test all three distributions simultaneously. Parameterize with a `map` variable.
- **Idempotency:** The Ansible role is fully idempotent — running the playbook multiple times produces the same result without side effects.
- **Handlers:** The `Restart Docker` and `Enable Docker` handlers only fire when a preceding task reports a change, keeping runs efficient.
- **Private Instance Access:** Private EC2s have no public IP. Always route SSH through the bastion host or use AWS Systems Manager Session Manager as a keyless alternative.
